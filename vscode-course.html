課程教案 · 逐時段講義

VS Code 入門三小時

從零安裝到能寫、能跑、能用終端機與 Git 的基本工作流。適合完全沒寫過程式的學員，全程以「先操作、再解釋」為主——安裝後先動手開檔案、換主題，累積成就感後才進入介面理論。

時長3 小時（含休息） 對象有基礎電腦操作，未寫過程式 環境自架授權簽到靶機 + Python 形式投影 + 現場跟做
00:00–00:20

安裝與初次啟動

00:00

下載與安裝

約 15 分鐘

前往官方網站下載對應作業系統版本（Windows / macOS）。強調：這是「編輯器」不是「作業系統」，也不是瀏覽器。

  • Windows：下載 .exe，安裝時建議勾選「加入右鍵選單」「加入 PATH」
  • macOS：下載 .zip，解壓縮後拖入應用程式資料夾
  • 常見卡點：學校/公司電腦沒有系統管理員權限 → 使用者層級安裝版
現場提示 安裝過程請學員全程跟做，不要用投影帶過——這一步最容易個別卡住，寧可多留時間巡場。
00:15

初次啟動一覽

約 5 分鐘

開啟後先讓學員看一眼畫面即可，不深入解釋——語言暫時保持英文，介面認識與中文化留到後面模組再處理。先示範一次 Ctrl+Shift+P（Mac 為 Cmd+Shift+P）開啟命令面板，讓學員有印象即可。

00:20–00:45

檔案與專案管理：實際打開文件

00:20

「開啟資料夾」＝ VS Code 裡的「專案」

約 10 分鐘

這是本模組最重要的觀念：VS Code 沒有「新建專案」按鈕，一個資料夾就是一個專案。直接用學員自己的下載資料夾練習，比新建空資料夾更有感。

  • File → Open Folder，選取「下載」資料夾（課程講義 PPT / 文件已預先放在裡面）
  • 左側 Explorer 會顯示該資料夾內容——第一次看到「一堆檔案變成可操作的樹狀清單」
00:30

用 Office 擴充套件直接在 VS Code 裡看 PPT / Word

約 15 分鐘

安裝 Office Viewer 類擴充套件（Extensions 面板搜尋安裝），在編輯區直接點開下載資料夾裡的 .pptx / .docx 檔案。

  • 點開課程講義 PPT，示範可以直接在分頁裡翻頁預覽，不需要另外開 PowerPoint
  • 順便示範開啟一個 .docx 講義文件比對
  • 體會 VS Code 不只能寫程式，也能當「輕量文件檢視器」使用
帶學員做 請每個人自己在下載資料夾裡找到今天的講義檔案並點開看一次，建立「VS Code 也能看我平常的檔案」的直覺。
00:40

建立、儲存檔案（小練習）

約 5 分鐘
  • 右鍵 Explorer 空白處 → New File，練習新建一個空白 .txt
  • 存檔快捷鍵 Ctrl+S；分頁上有圓點代表尚未儲存
常見誤解 很多初學者以為要「儲存專案」，其實 VS Code 沒有專案檔——存的永遠是個別檔案，資料夾只是視窗顯示範圍。

切換色彩主題

約 10 分鐘

繁體中文化（可選）

01:05

依個人習慣決定是否切換

約 10 分鐘

介面已經玩過一輪、也換好喜歡的顏色，現在請學員自行決定：習慣英文介面就跳過這一步，想要中文介面的人再一起做。

01:15–01:40

介面認識

01:15

五大分區導覽

約 15 分鐘

前面幾個模組已經摸過 Explorer、命令面板、主題設定——現在正式把這些操作「掛回」對應的介面分區名稱，用「房間」比喻整個介面：

  • Activity Bar（左側最窄那排圖示）：切換不同功能面板的按鈕
  • 側邊欄（Side Bar）：檔案總管、搜尋、原始碼控制、擴充套件——剛才開資料夾、裝 Office 套件都在這裡操作
  • 編輯區：真正打字寫東西、剛才看 PPT 的地方，可分割成多個分頁/多個窗格
  • 狀態列（底部）：目前語言、編碼、游標位置、Git 分支
  • 右上角工具列：分割編輯器、開啟終端機、切換版面配置
01:25

最上方選單列（File / Edit / View…）

約 10 分鐘

視窗最上方一整排文字（File、Edit、Selection、View、Go、Run…）是傳統選單，跟命令面板是兩條通往同樣功能的路——初學者常常忽略它，但它更適合「用滑鼠慢慢找」的習慣。

  • File：Open Folder、Save、Save As，就是剛才開下載資料夾的另一條路
  • View：開啟 Explorer、Terminal、Extensions 等各面板，跟 Activity Bar 是同一批功能的另一個入口
  • Run：之後執行 Python 爬蟲腳本時，也可以從這裡執行，而不只是打終端機指令
視窗變窄時 當視窗或畫面解析度較小，選單列會摺疊成一個「⋯」（More Actions）圖示，把 Terminal、Help 等選項收進去——提醒學員別以為選單不見了，點開「⋯」就找得到。

Git 基礎操作

約 10 分鐘
  • 終端機輸入 git init 初始化版本控制

實作：簽到靶機 API 練習

授權說明 · Authorized Practice Target

本練習使用講師自架的教學用簽到系統（靶機），僅供本課程授權環境練習，情境為典型的 API 缺少授權驗證（Broken Authentication / Missing Access Control），對應 OWASP API Security Top 10 中的 API2 類別。請提醒學員：這套手法僅可用於自己架設或明確授權的系統。

02:45

觀察靶機：從 /docs 看到所有 API

約 5 分鐘

靶機這次的弱點示範：介面上開放了 API 文件頁（如 FastAPI 的 /docs），任何人都能看到完整的端點清單與參數格式，且呼叫時不需要任何登入 token。

端點方法參數用途
/api/checkinPOST{"user_id": "..."}簽到（無驗證）
/api/checkoutPOST{"user_id": "..."}簽退（無驗證）
帶學員做 在瀏覽器打開靶機的 /docs，用內建的「Try it out」先手動呼叫一次，確認不需要登入就能成功——這一步是理解漏洞的關鍵，比直接看程式碼更直覺。
02:50

寫最小可行的 Python 呼叫腳本

約 7 分鐘

在 VS Code 新建 checkin.py，安裝 requests 套件後撰寫通用的呼叫寫法：

import requests # 靶機網址請以講師公告的實際位址為準 BASE_URL = "http://靶機位址" def checkin(user_id): resp = requests.post( f"{BASE_URL}/api/checkin", json={"user_id": user_id} ) print(resp.status_code, resp.json()) def checkout(user_id): resp = requests.post( f"{BASE_URL}/api/checkout", json={"user_id": user_id} ) print(resp.status_code, resp.json()) if __name__ == "__main__": checkin("student01")
現場調整 實際端點路徑、參數欄位名稱、回應格式請依你自架靶機的真實 API 規格調整此範例——上方僅為典型 REST 簽到 API 的通用寫法示範。

終端機執行：

python checkin.py
02:57

討論：這個漏洞為什麼危險？

約 3 分鐘

收尾討論，把技術動手做拉回資安概念：

  • 因為沒有驗證使用者身分（token / session），任何人都能代替別人簽到退
  • 公開的 /docs 等於把「攻擊地圖」直接給了所有人
  • 正確修法：每個請求都要驗證登入身分，且只能操作「自己」的紀錄

課後自我檢查清單

  • 能獨立安裝 VS Code
  • 能開啟資料夾，並用 Office 擴充套件直接瀏覽 PPT / Word 文件
  • 能切換喜歡的色彩主題與字型，依個人習慣決定是否切換為繁體中文
  • 能講出五大介面分區與選單列的用途，並用命令面板找到任何功能
  • 能使用多游標與搜尋取代加速編輯
  • 能安裝擴充套件（Python）並開啟整合終端機執行基本指令
  • 理解「API 缺少授權驗證」為何是安全風險，並僅在授權環境中練習
時間 為建議節奏，可依現場狀況彈性 ±5 分鐘調整 靶機練習 僅限講師自架授權環境使用
